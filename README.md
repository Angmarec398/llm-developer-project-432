# ИИ-генератор карточки товара

[![hexlet-check](https://github.com/Angmarec398/llm-developer-project-432/actions/workflows/hexlet-check.yml/badge.svg)](https://github.com/Angmarec398/llm-developer-project-432/actions)

Бэкенд-сервис, который принимает документы поставщиков (pdf, docx, xlsx), строит по ним
поисковый индекс и генерирует черновик карточки товара — с указанием источников, списком
недостающих данных и уровнем уверенности. Документы поставщиков считаются недоверенными
данными: персональные данные маскируются до попадания в промпт, фрагменты с
промпт-инъекциями отсекаются до генерации, а контакты в готовой карточке фильтруются
на выходе.

Учебный проект Хекслета: https://ru.hexlet.io/programs/llm-developer

## Стек

- Python 3.12, FastAPI, Pydantic v2
- PostgreSQL 16 + pgvector — векторный и полнотекстовый поиск, гибрид со слиянием рангов (RRF)
- Temporal — оркестрация процессов: разбор документов, генерация карточки, сигналы approve/reject
- LM Studio — локальные LLM: основная (генерация) и служебная (критик, судья, детектор инъекций)
- sentence-transformers (`intfloat/multilingual-e5-small`) — эмбеддинги локально
- pytest, ruff

## Требования

- Docker и docker compose
- Python 3.12+
- LM Studio с запущенным сервером (`http://localhost:1234`) и двумя загруженными моделями:
  - основная: `unsloth/qwen3-4b-instruct-2507`
  - служебная: `llama-3.2-3b-instruct`

  Имена моделей можно поменять в `.env`.

## Установка и запуск с нуля

```bash
git clone https://github.com/Angmarec398/llm-developer-project-432.git
cd llm-developer-project-432

python -m venv .venv
source .venv/Scripts/activate   # Windows (Git Bash); Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt

cp .env.example .env            # при необходимости поправьте имена моделей

docker compose up -d            # postgres+pgvector, temporal, temporal-ui (:8233)
make migrate                    # миграции БД
make api                        # FastAPI на :8000 — терминал 1
make worker                     # temporal-воркер — терминал 2
```

Проверка: `curl localhost:8000/health` → `{"status":"ok"}`;
`curl localhost:8000/health/ready` → база доступна и расширение vector активно.

При первом запуске sentence-transformers скачает модель эмбеддингов (~0.5 ГБ).

## Использование

Загрузить документ поставщика (202 + id документа, разбор и индексация идут в фоне):

```bash
curl -F "file=@data/kettle_spec.xlsx" localhost:8000/documents
```

Статус разбора: `curl localhost:8000/documents/{document_id}`.

Запустить генерацию карточки по выбранным документам:

```bash
curl -X POST localhost:8000/jobs \
  -H "Content-Type: application/json" \
  -d '{"document_ids": ["<id1>", "<id2>"], "hint": "чайник"}'
```

Результат — `curl localhost:8000/jobs/{job_id}`: статус цепочки
(parsing → indexing → searching → screening → generating → verifying → critiquing →
filtering → done | awaiting_confirmation), карточка со ссылками на фрагменты-источники
и отчёт защиты (что замаскировано, какие фрагменты исключены, какие документы в карантине).

Если задача в `awaiting_confirmation` (низкая уверенность, спорные ссылки, сработала защита):
`POST /jobs/{id}/approve` или `POST /jobs/{id}/reject`.

Синхронный вариант без Temporal: `POST /cards` с тем же телом — вернёт карточку сразу.

## Метрики качества и стоимость

```bash
make eval        # быстрый прогон по эталонным карточкам (data/golden_cards.json)
make eval-full   # полный прогон
```

Отчёт складывается в `evals/report_<timestamp>.md`: полнота характеристик, цитирование,
истинность (модель-судья). Каждый вызов модели пишется в таблицу `llm_calls`
(токены, длительность, стоимость) — по `job_id` видна вся цепочка вызовов задачи.

## Отчёт о приёмочном прогоне (22.11.2026)

Прогон с нуля: тома удалены (`docker compose down -v`), инфраструктура поднята заново,
6 миграций применены на чистую базу, все 5 выданных документов загружены, карточки
сгенерированы. Прогон поймал дефект, невидимый в «тёплом» окружении: при пустом
результате поиска задача сообщала «все фрагменты отклонены детектором инъекций» —
теперь ошибка честная: «поиск не вернул ни одного фрагмента по выбранным документам».

### Сценарии прогона

| Документы | Итог |
|---|---|
| kettle_spec + kettle_manual (инъекция) | `awaiting_confirmation`: фрагмент с инъекцией исключён, документ в карантине (1/1 ≥ порога 0.5), «1 рубль» в карточке нет |
| blender_kp + blender_passport (ПДн) | `done`: карточка полная, со ссылками; контакты замаскированы до промпта |

| hint без совпадения с текстом | `awaiting_confirmation`: «поиск не вернул ни одного фрагмента» |

### Стоимость одной карточки

По таблице `llm_calls` (цены номинальные — модели локальные, в LM Studio):

- блендер, полный цикл: 2 вызова (генератор + критик), ~4 700 токенов, $0.0008, ~3.5 мин;
- чайник, блок защитой: 2 вызова детектора, ~2 400 токенов, $0.0002, ~1 мин;
- итого порядка **$0.0005 за карточку**; генератор на основной модели даёт ~80%
  стоимости, критик и детектор на служебной — в 4–5 раз дешевле.

### Самая слабая метрика

Истинность (0.45). Вердикт выносит служебная модель 3B — она сама слабая, и метрика
недетерминирована (на одном документе 0.14–0.67 между прогонами); генератор 4B при этом
склонен добавлять правдоподобные, но неподкреплённые утверждения (линейку чайников назвал
«термостатическим водонагревателем»). Структурно низка и метрика характеристик (0.50):
на документах-линейках (КП, спецификация) эталон ждёт характеристики каждой модели
линейки, а карточка описывает один товар.
