# 0002. Миграции схемы — SQL-файлы и свой раннер

## Статус
Принято (шаг 2, 2026-11-16)

## Контекст
Таблиц становится несколько, появляются индексы pgvector, генерируемые
колонки и запросы с оконными функциями. Схема перестаёт помещаться
в «создать таблицу, если не существует» при подключении.

## Решение
Обычные SQL-файлы в `db/migrations/`, которые применяет простой раннер
`app/core/migrate.py` по порядку имён; применённые версии хранятся
в таблице `schema_migrations`. Alembic не используем.

## Последствия
Плюс: весь SQL (индексы pgvector, генерируемые колонки, оконные функции)
пишется напрямую, без прослойки, которая его прячет.
Минус: нет автогенерации миграций из моделей и downgrade-цепочек —
откаты делаем вручную отдельными миграциями, если понадобятся.
