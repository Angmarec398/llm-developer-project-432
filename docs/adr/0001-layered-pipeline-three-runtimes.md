# 0001. Слои и три способа запуска пайплайна

## Статус
Принято (шаг 1)

## Контекст
Пайплайн генерации карточки (extract → generate → critique) должен
работать и в учебном синхронном режиме, и в фоновой обработке.

## Решение
Приложение делится на слои: routers → services → repositories.
Стадии пайплайна живут в `app/services/pipeline.py` и не знают
о транспорте, поэтому один и тот же код запускается тремя способами:
синхронно в эндпоинте FastAPI, через Celery-воркер с RabbitMQ
и как Temporal workflow.

## Последствия
Слой запуска можно менять, не трогая логику пайплайна. Плата —
обвязка трёх runtime (роутеры, celery-таски, temporal activities)
и необходимость держать их согласованными.
