# 3. Порог релевантности и выбор модели эмбеддингов (шаг 6, пересмотрено)

## Контекст

Поиск по фрагментам — три режима: по векторам (косинусная близость),
по словам (ts_rank), гибрид (слияние по обратным позициям, RRF).
Порог один — `retrieval_threshold`; по условию шага он откалиброван
на своих данных, а не взят с потолка.

Первая версия ADR (multilingual-e5-small, порог 0.80) построена была
на замерах e5 и отброшена вместе с моделью: GGUF-конверсия
keisuke-miyako/multilingual-e5-small-gguf-q8_0 через LM Studio
выдавала дегенеративные векторы (близость перефразировки 1.0000,
любой мусор ≥ 0.91) — поиск молча не работал, а полноценная e5
скачивала пол-гигабайта весов и жила на собственной шкале косинусов,
не подходившей под выбранный порог.

## Решение

Модель эмбеддингов — google/embeddinggemma-300m через
sentence-transformers (не LM Studio). Контракт модели: разные
префиксы запроса и документа

- query: "task: search result | query: <текст>"
- document: "task: search result | title: none | text: <текст>"

Префиксы подставляются в app/rag/embedder.py, модель грузится один
раз на процесс (лениво), векторы считаются пачкой и нормируются.
Размерность 768 — колонка `chunks.embedding vector(768)` (миграция
0007 пересоздала её под смену модели; старые векторы досчитывает
`make reindex`).

Порог 0.35: embeddinggemma-300m даёт косинус 0.4-0.55 для релевантных
пар и заметно ниже для мусора. Порог применяется к косинусной оценке
векторного режима после отбора top_k с запасом (порог фильтрует
только векторную половину: полнотекстовый кандидат — точное
совпадение термина, он релевантен по построению, поэтому в гибриде
порог не фильтрует FTS-часть). RRF: вклад 1/(60+ранг) от каждого
списка, где фрагмент найден, найденный обоими всплывает выше.

## Последствия

- Смена модели эмбеддингов = новая миграция колонки vector(<dim>)
  и перекалибровка порога; без миграции индекс и колонка расходятся.
- GGUF-конверсии эмбеддинговых моделей непригодны без проверки
  качества (см. контекст).
- pgvector не дампит list[float] в vector — в SQL вектор передаётся
  строкой '[x,y,...]' с кастом ::vector (app/repositories/chunks.py).
