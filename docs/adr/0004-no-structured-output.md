# 4. Отказ от output_type: structured output LM Studio ломает свободные dict (шаг 8)

## Контекст

Агенты SDK передают схему ответа через output_type → response_format
(json_schema), и LM Studio включает генерацию по грамматике схемы.
После смены основной модели на qwen3-4b-instruct-2507 метрика
характеристик упала до 0.00: карточки проходили валидацию с пустым
characteristics = {} при confidence 0.98 — мусор неотличим от честной
карточки по всем остальным полям.

Диагностический эксперимент (один и тот же промпт и контекст,
blender_passport.pdf):

- вызов через output_type: characteristics = {};
- сырой chat.completions без response_format: все 12 характеристик,
  совпадение с эталоном 12/12.

Модель исправна — искажает ответ грамматика: для свойства object без
фиксированных ключей (characteristics: dict[str, str]) построенная
грамматика допускает только пустой объект. Остальная схема (строки,
списки строк, объекты с фиксированными ключами) грамматикой не
страдает — поэтому дефект долго оставался невидимым.

## Решение

output_type убран у всех агентов (card, critic, judge). Схема
дублируется текстом в промпте (schema_instructions), грязный JSON
разбирает extract_json, невалидный ответ лечится повторным вызовом с
текстом ошибки (validate_or_retry) — механизм шага 4, изначально
написанный под «LM Studio strict mode не поддерживает».

## Последствия

- Ответы моделей свободнее (markdown-заборы, текст вокруг JSON) —
  разбор в app/services/structured.py это переживает.
- Пустоту свободных dict схема больше не ловит: заполненность
  характеристик контролируется промптом, критиком и метриками.
- При смене сервера (не LM Studio) output_type можно вернуть, но
  свободные dict проверить на пустоту отдельным тестом.
